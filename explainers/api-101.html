APIs: Your Digital Waiter

Simple definition + restaurant analogy for non‑engineers

🌍 Definition

An API is a contract: “If you ask like this, I'll respond like that.”

  • Request: method + URL + headers + body
  • Response: status code + data (usually JSON)
  • Docs = the rules of the contract

🍽️ Restaurant analogy

Menu ≈ docs • Waiter ≈ API • Kitchen ≈ Server

Menu = docs (rules, not an endpoint). Order = Request. Waiter = API. Kitchen = Server.

Say “Margherita, thin crust”. Kitchen replies 200 OK with pizza. Closed? 503. Bad order? 400.

In this demo we call /pizza to list pizzas and /orders to place one.

🔒 Why it matters

APIs stitch products together

They power integrations, mobile apps, automations, and partner ecosystems.

At Signeasy, APIs let customers create files, invite signers, and fetch signed docs programmatically.

Common status codes
How servers communicate results

        

          
200 — OK
All good.

          
201 — Created
A new thing was created.

          
204 — No Content
Success with no body (e.g., delete).

          
400 — Bad Request
The order slip is wrong.

          
401 — Unauthorized
Missing or invalid API key.

          
404 — Not Found
Wrong URL or missing resource.

          
409 — Conflict
Duplicate/contradicting request.

          
422 — Unprocessable
Data shape is valid, values are not.

          
429 — Too Many Requests
Busy kitchen — wait, then retry.

          
500 — Server Error
The kitchen broke — not your fault.

Webhooks vs Polling
Two ways your app learns about changes

        

          

            
Webhooks (push)
The restaurant calls you when the order is ready

            

              
Expose a public HTTPS endpoint (e.g., /webhooks/restaurant).

              
Verify signatures to trust the sender.

              
POST /webhooks/restaurant
Signature: t=...,v1=...
{
  "type": "order.ready",
  "data": { "id": "order_901" }
}

            

          

          

            
Polling (pull)
Your app checks periodically

            

              
Call GET /orders?status=preparing every N seconds/minutes.

              
Be polite: use backoff and conditional requests.

              
GET /orders?status=preparing
200 OK
[{"id": "order_901", "status": "preparing"}]

            

          

        

      

    


    
    

      

      

    


    
    

      

        
Glossary
Keep this open while discussing

        

          
Endpoint
A specific URL where you send a request (e.g., /pizza).

          
Method
The action you want (GET, POST, etc.).

          
Header
Metadata like auth, content type.

          
Body
The payload you send, often JSON.

          
Status code
3‑digit number describing the result.

          
SDK
A library that wraps HTTP calls.

          
Pagination
Breaking long lists into pages.

          
Rate limit
Max requests allowed in a time window.

          
Webhook
Provider calls your URL with events.

          
OAuth
User‑granted access flow.

          
Idempotency
Same request safely retried.

          
Versioning
Evolving APIs without breaking clients.
