What, why, and how they help systems talk

🌍 Definition

An API is a contract: “Ask like this, I’ll respond like that.”

  • Request: method + URL + headers + body
  • Response: status code + data (usually JSON)
  • Docs = the menu of what’s available

🧋 Restaurant metaphor

Menu = API docs · Order = Request · Kitchen = Server

Say “Latte, small” (well‑formed). Kitchen replies 200 OK with your drink. If they’re closed: 503. If order is invalid: 400.

🔗 Why it matters

APIs stitch products together

In a restaurant app, APIs let you browse the menu, place orders, track status, and pay — from any device.

Common status codes
How the kitchen communicates results

        

          
200 — OK
Order fetched or updated successfully.

          
201 — Created
A new order was created.

          
204 — No Content
Order cancelled or nothing to return.

          
400 — Bad Request
Malformed order (e.g., unknown item).

          
401 — Unauthorized
Missing/invalid staff key.

          
404 — Not Found
Wrong URL or unknown item/order.

          
409 — Conflict
Order state prevents this action.

          
422 — Unprocessable
Order is valid JSON, but business rules fail.

          
429 — Too Many Requests
Busy kitchen; slow down (use backoff).

          
500 — Server Error
Kitchen fault; try later.

Webhooks vs Polling
Learn when something changed

        

          

            
Webhooks (push)
Kitchen calls you when events happen

            

              
You expose a public HTTPS endpoint (e.g., /webhooks/restaurant).

              
Validate signatures to trust the sender.

              
POST /webhooks/restaurant
Signature: t=...,v1=...
{
  "type": "order.ready",
  "data": { "id": "order_901" }
}

            

          

          

            
Polling (pull)
You check periodically

            

              
Call GET /orders?status=preparing every N seconds.

              
Use backoff & conditional requests to be polite.

              
GET /orders?status=preparing
200 OK
[{"id": "order_901", "status": "preparing"}]

Glossary
Keep this open while discussing

        

          
Endpoint
A specific URL where you send a request (e.g., /pizza).

          
Method
The action you want (GET, POST, etc.).

          
Header
Metadata like auth, content type.

          
Body
The payload you send, often JSON (e.g., order pizzas).

          
Status code
3‑digit number describing the result.

          
SDK
A library that wraps HTTP calls.

          
Pagination
Breaking long lists into pages.

          
Rate limit
Max requests allowed in a time window.

          
Webhook
Kitchen calls your URL with events.

          
OAuth
User‑granted access flow.

          
Idempotency
Same request safely retried.

          
Versioning
Evolving APIs without breaking clients.
